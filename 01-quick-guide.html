REEF Ocean Explorers Booking Workflow

Staff Quick Guide — At a Glance

What to do at each stage, and where it lives · staff pilot launch reference

Updated 2026-09-08 for the OXP Booking System staff pilot (originally built for the Sept 3, 2026 staff walkthrough)

The Flow, Start to Finish

1
When an inquiry comes in, start here live

A teacher or group leader emails, calls, or submits a form. Today, that means the "Program Booking Request" or "Internal Discovery Program Booking" form in Asana — or, if it comes straight to you by email, manually create a task in OXP New Reservation Workflow using the standard checklist. If a Coordinator instead creates the record directly in EPO with Status = Inquiry, the matching Asana task is now created for you automatically — this sync (Zap 1) is live in production, not a pilot feature.

2
When it is qualified, this happens live

Confirm the basics — organization, contact, dates, group size, program type. Decide if it's a real fit. If yes, move it forward: work the Asana checklist, and in EPO flip the Opportunity Stage and check "Ready for REEF Bookings." Once checked, a priced Bookings record is created for you automatically (Zap 2, live) — no more manually re-entering the same details into Airtable.

3
When pricing is needed, use this live

REEF Bookings in Airtable. Enter group size, dates, and activities — the pricing formulas (program fees, supplies, campus facility fee, free-chaperone policy, uplift, payment schedule) calculate automatically. No more Excel Rate Calculator for Expeditions.

4
When proposal is sent, watch this system 1: live system 2: tested only

Today, every real proposal goes out as a Google Doc/PDF, generated in one click from the "OXP Proposal Generator" Google Sheet, pulling straight from the Airtable numbers. We're separately testing a webpage-style proposal with a "Ready to Move Forward" button — fully built and tested against two TEST bookings only, never yet used with a real customer. Use System 1 for every real booking during the pilot unless Martha tells you otherwise.

Before anything reaches a customer — the review gate live, tested end-to-end

Whenever a proposal or contract link is generated for a booking, the system automatically creates an Asana review task assigned to Rose, with the proposal/contract links attached. Nothing goes to a customer until a person has looked it over and checked it off — this is the main safety net against a half-generated or wrong proposal reaching a real customer. If you don't see a review task and a link is waiting to go out, stop and flag it — that's a bug, not a shortcut.

5
When customer says yes (or requests changes), do this live

Verbal commitment → move Status to Verbal Yes, prepare the agreement. Signed + deposit → Contracted, then Confirmed. If they ask for changes, update the booking and resend — status stays at Proposal Sent until they confirm.

6
When Status moves to Confirmed, this syncs back live Completed / Cancelled: not yet

Moving a booking to Confirmed automatically pushes the status, headcount, and price to EPO and comments on the Asana task. Moving to Completed or Cancelled does not sync yet — update EPO's status by hand for those two until this is built. See the Manual Fallback Guide.

7
When it is confirmed, Scheduling takes over not yet automatic

Staffing demand (roles/counts needed) gets populated on the booking and should push automatically into REEF Scheduling — that connection isn't wired up yet, so today this is still a manual heads-up to whoever assigns staff.

Known Blockers This Pilot Week

  • Completed / Cancelled sync isn't built. Only moving a booking to Confirmed syncs back to EPO + Asana automatically. Update EPO by hand for the other two for now.
  • The "Ready to Move Forward" button doesn't do anything live yet. The webhook behind it is still blocked (schema capture + an expired authorization) — customers can't trigger anything by clicking it.
  • Two proposal systems exist. System 1 (Google Doc/PDF) is what real customers get. System 2 (HTML page) is tested but not customer-facing — don't send it to a real customer yet.
  • A booking's facts can live in up to three places (Asana, a Dropbox tracking spreadsheet, the Bookings Airtable record) with nothing cross-referencing them. When in doubt, trust REEF Bookings' Status field, not the others.
  • The public intake forms are still draft mockups — not something a teacher can reach yet.
