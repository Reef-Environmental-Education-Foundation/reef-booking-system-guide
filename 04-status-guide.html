8-Stage Bookings Status Guide

What each REEF Bookings Status means, who moves it, and what fires automatically

2026-09-08

1

Quoting

Starting point. The Bookings record exists — either created automatically once EPO's "Ready for REEF Bookings" is checked (Zap 2, live), or manually. Staff refines group size, dates, and activities; the pricing formulas calculate as fields fill in. No customer has seen numbers yet.

record creation: live (Zap 2)
2

Proposal Sent

Staff has sent a proposal to the customer — today, System 1's Google Doc/PDF. Proposal Sent Date gets set. If the reef-program-pages pipeline was run to generate a page/contract for this booking, a review task exists in Asana (assigned to Rose) and must be checked off before that link goes to the customer.

review gate applies whenever a page/contract is generated
3

Verbal Yes

Customer has given verbal commitment (by phone/email today; via System 2's "Ready to Move Forward" button once that's customer-facing). Staff prepares the agreement. No status change here is automatic — a person always makes this call, even once System 2 is live.

4

Contracted

Signed agreement and deposit received. Zoho Sign integration is still a placeholder, so getting the signature is a manual/offline step today, not something the system tracks live.

5

Confirmed

The booking is locked in. Moving Status to Confirmed automatically pushes Status, headcount (# Attendees), and price (Total Package Price, sanity-capped at $30,000) to EPO, and comments on the linked Asana task. This is also typically when the confirmed customer page gets published via the GitHub Actions pipeline.

EPO + Asana sync: live (Zap 3, Confirmed path)
6

In Progress

The program is underway. No automation is tied to this stage today — it's a manual marker for staff/Scheduling visibility.

7

Completed

The program has finished. This should push Status to EPO and comment on the Asana task the same way Confirmed does — but that path (Zap 3, Path A) isn't built yet. Update EPO by hand for now: set real Status to "Completed" and comment on the Asana task yourself. See the Manual Fallback Guide.

EPO + Asana sync: not yet built
8

Cancelled

Booking called off — can happen from any stage, any time. Same gap as Completed: the sync back to EPO (Status → "Canceled/deferred") isn't built yet (Zap 3, Path C). Update EPO by hand. See the Manual Fallback Guide.

EPO + Asana sync: not yet built
The review-gate task is not tied to one specific stage transition — it's created whenever staff run the booking-package pipeline to generate a confirmed page and/or contract, whatever the current Status. Treat "is there a completed review task for this booking's latest proposal/contract" as its own always-relevant check, separate from Status.
