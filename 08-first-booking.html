First-Real-Booking Checklist

What has to be true before letting a real, non-test booking flow through the pilot system

2026-09-08

Picking the Booking

The safest first real booking is one with: real flexibility on dates and communication pace (not a rush job), a moderate group size, an OXP program (Discovery or Expedition) rather than a Facility Rental — Facility Rentals are Dylan's smaller-scope workflow and haven't been part of this pilot build — and enough lead time before travel to absorb a manual fallback step if Path A/Completed, Path C/Cancelled, or the CTA webhook gap gets in the way.

Staff owner: Rose, as OXP Coordinator, with Chesley as her supervisor and escalation point for anything pilot-related.

Before You Start

  • EPO record exists for this booking, with an accurate Opportunity Stage
  • REEF Bookings record exists (created via Zap 2 or manually), with correct group size, dates, and activities
  • Pricing checks out — spot-check the formula totals against what you'd expect
  • Asana task exists, correctly linked to the booking, in the right project (OXP New Reservation Workflow) and section

Sending the Proposal

  • Using System 1 (Google Doc/PDF) — not System 2, for any real customer
  • If a page/contract package was generated for this booking, a review task exists in Asana assigned to Rose
  • The review task has actually been checked off by a person before the link goes to the customer
Do not skip the review-gate check. This is the one step in this whole checklist that exists specifically to catch a bad proposal before a real customer sees it. If you can't confirm a review task was completed, don't send the link — go find out first.

As the Booking Progresses

  • Status changes (Verbal Yes → Contracted → Confirmed) are made deliberately by a person, not assumed
  • When Status reaches Confirmed, confirm the EPO + Asana sync actually fired (Zap 3) — check EPO's OXP Booking Status and the Asana task comment
  • Scheduling has been given a manual heads-up with dates, group size, and staffing needs — this doesn't push automatically yet
  • Everyone involved knows Completed/Cancelled won't sync automatically when the time comes — see the Manual Fallback Guide, and know who owns doing that by hand for this specific booking

After the Program

  • Once the program finishes (or is cancelled), update EPO's Status by hand and comment on the Asana task — this booking's outcome, whichever it is, won't sync itself
  • Capture anything that broke or felt confusing in the Bugs and Confusing Moments section — a real booking surfaces things test records won't
  • Debrief with Martha/Rose/Chesley on whether this booking's experience is good enough to call the pilot ready for a second real booking, or whether something needs fixing first
This checklist assumes everything named in the Known Blockers list (Quick Start Guide) and the Manual Fallback Guide is still true at the time you run it — re-check the Asana project's Start Here section for anything that's changed since 2026-09-08.
