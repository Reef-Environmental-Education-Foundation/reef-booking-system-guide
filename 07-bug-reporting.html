Bug-Reporting Process

How to report bugs or confusing moments during the pilot, and how they get triaged

2026-09-08

Where to Log It

Every bug or confusing moment gets its own task in the Bugs and Confusing Moments section of the "REEF OXP Booking System Pilot Launch" Asana project. Use the template below in the task description — don't skip fields even if the answer is "not sure."

Staff logs issue: [your name, date, which booking/record if applicable]
Expected behavior: [what you thought would happen]
Actual behavior: [what actually happened]
Screenshot / link: [attach or paste a link — Airtable record, Asana task, page URL]
Urgency: blocker / annoying / later

Urgency Levels

Blocker
Stops real work, or risks something reaching a real customer wrong. Flag immediately, don't just leave it in the backlog.
Annoying
Workable around, but should get fixed. Logged normally, triaged in order.
Later
Real, but low-stakes or cosmetic. Goes to Later / Parking Lot.
Special category — a stuck or missing review task. If you generated a proposal/contract package and no Asana review task appeared for Rose, or an existing review task seems stuck, duplicated, or pointed at the wrong booking — log this as its own bug, urgency blocker, every time. This isn't a generic bug: the review task is the only thing standing between a bad proposal and a real customer, so a broken gate is more urgent than a broken button.

Escalation

  • Blocker (including any stuck/missing review task): log the Asana task, then also message Martha and Rose directly the same day — don't wait for someone to see it in the backlog.
  • Annoying: log it in Asana; it'll get triaged and picked up in the Build Fixes section.
  • Later: log it in Asana; it moves to Later / Parking Lot and isn't pilot-blocking.
If you're not sure whether something is a bug or expected behavior (a lot is intentionally manual right now — see the Manual Fallback Guide), log it anyway and flag it as "not sure if bug" — that's useful information either way.
