REEF Ocean Explorers Booking Workflow — Staff Pilot Handoff

Manual Fallback Guide

What to do by hand for everything that isn't automated yet

2026-09-08

Booking moves to Completed or Cancelled not yet built

Only the move to Confirmed automatically syncs to EPO and Asana. Completed and Cancelled do not — that build (Zap 3, Paths A and C) hasn't happened yet.

Do this by hand: open the linked EPO record and set its real Status field — "Completed" for Completed, "Canceled/deferred" for Cancelled — and set OXP Booking Status to match the Bookings Status text. Then add a comment on the booking's Asana task noting the change, the same way the automated sync does for Confirmed, so anyone reading the task doesn't have to cross-check Bookings separately.

Customer clicks "Ready to Move Forward" or "Request a Change" blocked

This only exists on System 2's HTML proposal, which isn't customer-facing yet — the webhook behind the button is still blocked (Airtable schema-capture + an expired connection authorization). Nothing happens automatically even in a real customer scenario once System 2 does go live-facing, until this is fixed.

Do this by hand: when a customer verbally or by email says yes or asks for changes, update the Bookings record yourself — move Status to Verbal Yes, or note the requested change in Internal Notes / Special Requests and follow up directly. Don't wait on the button to do anything.

Deciding which proposal system to use

Two systems exist. System 1 (Google Sheet → Doc/PDF) is what every real customer gets today. System 2 (six-section HTML page) is fully built but tested only against two TEST bookings — never sent to a real customer.

Do this by hand: use System 1 for every real booking during the pilot, no exceptions, until Martha names an owner and a cutover date for System 2. Only use System 2 against ZZZ STAFF TEST records during pilot testing.

A booking's facts disagree across systems

A booking can have facts living in up to three places — Asana, a Dropbox tracking spreadsheet some Coordinators still keep, and the Bookings Airtable record — with nothing cross-referencing them automatically.

Do this by hand: treat REEF Bookings' own fields as correct and update the other two to match. Don't assume a spreadsheet or an Asana task description reflects the latest state.

A teacher or group leader wants to submit an inquiry online

The two redesigned public intake forms are still draft, unpublished mockups — not something a teacher can actually reach.

Do this by hand: keep using the two existing Asana intake forms ("Program Booking Request" and "REEF Facility Rental & Event Request Form") or take the inquiry by phone/email and create the EPO record or Asana task yourself. Don't point anyone at the draft mockups.

Tracking deal stage in Asana

The plan calls for a "Sales Stage" custom field on the Asana project that mirrors Bookings Status — it doesn't exist yet (blocked on Martha/Rose adding it manually in Asana), so nothing syncs to it.

Do this by hand: keep using REEF Bookings' own Status field as the deal-stage authority; don't expect Asana to reflect it until the field exists and the sync (Zap Step 5) is built.

A Confirmed booking needs staffing

Staffing demand doesn't push to REEF Scheduling automatically yet.

Do this by hand: once a booking hits Confirmed, send a direct heads-up to whoever assigns staff in Scheduling with the dates, group size, and role needs.

None of these gaps are hidden from staff on purpose — they're the known, named state of the build as of 2026-09-08. If one of these manual steps gets missed, that's worth a bug report (see the Bug-Reporting Process), not a reason to assume the system handled it.
